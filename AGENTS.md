# Far7a / فرحة — architecture rules

- Roles live in `public.user_roles` + `has_role()` / `is_admin()`, never on `profiles` — a role column on a user-owned row allows privilege escalation.
- Admin data is read with the browser Supabase client; RLS (`is_admin()`) is the real gate, the `/admin` route layout is UI only.
- Public invitation pages read ONLY through the security-definer functions `get_public_invitation(slug)` / `get_public_invitation_sections(slug)`, called from a server function with the publishable key — so unpublished rows and client/admin data can never leak.
- Slugs are generated by the DB function `generate_invitation_slug(base)` so uniqueness and `-2` suffixes stay race-free.
- Invitation content is data (`invitations` + `invitation_sections` + `media` + `templates`), never hardcoded per page: one template → many invitations.
- UI text goes through `src/lib/i18n.tsx` (Arabic default, RTL; English switchable). No hardcoded colors in components — only tokens from `src/styles.css`.
- Admin UI lives in `src/components/admin`, invitation forms in `src/components/invitations`, public rendering in `src/components/public`; data access in `src/lib/invitations.ts`.
